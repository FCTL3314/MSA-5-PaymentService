# MSA-5-PaymentService

Проектная работа 4-го спринта: Saga-оркестрация обработки платежа для платёжной платформы OrchestrPay.

| Задание | Что внутри |
|---|---|
| [Task1](Task1) | Реестр транзакций Saga: тип каждой (компенсируемая / необратимая / повторяемая), компенсации, сценарии отказов, pivot-точка |
| [Task2](Task2) | State Machine платежа: состояния, таблица переходов, диаграмма состояний |
| [Task3](Task3) | ADR: оркестратор — отдельный сервис на Camunda, а не часть Payment Service. C2-диаграмма решения |
| [Task4.1](Task4.1) | BPMN-диаграмма процесса: компенсационные развилки, ручная проверка с cut-off 20 минут, pivot, параллельный возврат и уведомление службы безопасности |
| [Task4.2](Task4.2) | Прототип на Camunda 8.9 (Zeebe, Tasklist, Operate) + Python-сервис с job workers. docker-compose, Dockerfile, скриншоты Tasklist и Operate, лог обработчиков, 11 прогнанных сценариев |
| [Task5](Task5) | 27 интеграционных и end-to-end тест-кейсов |
| [Task6](Task6) | Fitness-функции: консистентность, зависшие процессы, целостность Saga, таймауты и дедлайны |

Диаграммы: исходники PlantUML и BPMN, рядом отрендеренные PNG. Быстрый запуск прототипа:

```bash
cd Task4.2 && docker compose up -d --build && ./demo/run-demo.sh auto
```

Директория третьего задания названа `Task3` без пробела, как в разделе «Как сдать работу» и как остальные директории.
